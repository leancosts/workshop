# Modelo: material prévio da diretoria

Proposta do workshop. Enviado na véspera do dia 4, para que a diretoria chegue ao dia 5 com uma posição sobre cada decisão. Na sala, são quinze minutos: três por decisão. Uma decisão que não fecha sai com um nome e uma data.

```markdown
| Decisão | O que precisa ser respondido | Resposta | Dono | Data |
|---|---|---|---|---|
| Piloto | Qual time e quem responde internamente pelo programa | | | |
| Orçamento | Plano, teto de uso por pessoa e quem paga nos 90 dias | | | |
| Nuvem | Se o código pode ir para sessões na nuvem, decidido com a segurança | | | |
| Medição | Quem mede os quatro indicadores, e onde | | | |
| Revisão de 90 dias | A data e o critério para expandir ou repensar | | | |
```

Para decidir:

- **Custo.** A documentação do Claude Code dá uma referência de implantações corporativas: cerca de US$ 150 a 250 por desenvolvedor por mês, e recomenda medir num grupo piloto antes de ampliar. O detalhe de planos e limites está no modelo 21.
- **Prazo.** O efeito na entrega aparece em meses, e as primeiras semanas costumam ser mais lentas, porque o time escreve specs, testes e a base que não existiam. Um time em vermelho no SDLC mínimo (modelo 28) faz as fundações antes de entrar no piloto.
- **Critério.** Expandir quando o lead time do pod ficar abaixo da linha de base em duas features seguidas, com taxa de falha igual ou menor e nenhum incidente de dado fora da classe permitida. A linha de base é medida; estimativa não conta.
