# Modelo: lista de obstáculos

Cada time anota, desde o dia 1, tudo o que travou o trabalho. A lista é entregável do programa e vira insumo do desenho do processo futuro no dia 5. Um obstáculo tem o grupo, a causa (não só o sintoma) e o tempo perdido.

```markdown
| Dia | Grupo | O que aconteceu, a causa e o tempo perdido |
|---|---|---|
| 1 | Acesso | Sem permissão no repositório; o pedido foi para outra área; 40 min |
| 3 | Conhecimento em pessoas | A regra de arredondamento só um analista sabia; 25 min |
```

Os seis grupos:

| Grupo | Exemplos |
|---|---|
| Acesso | Repositório, ambiente, dados de teste, rede, conta |
| Aprovação manual | Uma etapa que espera uma pessoa sem critério escrito |
| Silo | Uma área dona de uma camada que o time precisa mudar |
| Conhecimento em pessoas | Uma regra que só alguém sabe |
| Ferramenta | Build que não roda, teste instável, ferramenta que falta |
| Limite de uso | O limite do plano do Claude atingido no meio do trabalho |

Time: <nome do time>. No dia 5, cada obstáculo ganha uma ação no desenho: causa, mudança, responsável e indicador.
